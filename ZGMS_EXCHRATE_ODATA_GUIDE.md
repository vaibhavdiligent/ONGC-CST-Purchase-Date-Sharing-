# ZGMS Exchange Rate – Inbound OData V2 Service (CPI → SAP)

Inbound OData V2 service so **SAP CPI posts exchange rates into SAP**. The
service maps the CPI XSD (`ExchangeRates` → `ExchangeRate*`) to a deep OData
entity, so the whole batch arrives in **one** call. You add the SAP update
logic in `process_rate( )`.

## Artifacts

| Object | Type | Purpose |
|--------|------|---------|
| `ZCL_GMS_EXCHRATE_MPC` | Class (model) | Code-based model. Defines `ExchangeRates` (header) + `ExchangeRate` (item) + navigation. |
| `ZCL_GMS_EXCHRATE_DPC` | Class (data) | Runtime. `CREATE_DEEP_ENTITY` receives the batch; `process_rate( )` is your TODO. |
| `ZGMS_EXCHRATE_SRV` | Service name | External service name registered in the gateway. |

Fully **code-based** – no SEGW project needed. Both classes are transportable
via abapGit as plain source.

## Field mapping (XSD ↔ OData ↔ ABAP)

`ExchangeRate` properties (names identical to the XSD elements):

- Keys (mandatory): `RATE_TYPE`, `FROM_CURR`, `TO_CURRNCY`, `VALID_FROM`
- Mandatory values: `EXCH_RATE`, `FROM_FACTOR`, `TO_FACTOR`
- Optional (nullable): `EXCH_RATE_V`, `FROM_FACTOR_V`, `TO_FACTOR_V`

`ExchangeRates` header carries `REQUEST_ID` (key) – generated by the service if
CPI sends it empty, and echoed back in the response.

All properties are `Edm.String` to match the XSD (`xs:string`).

## Registration steps

1. Create both classes in SE24/SE80 (or pull via abapGit) and activate.
   - `ZCL_GMS_EXCHRATE_MPC` inherits `/IWBEP/CL_MGW_PUSH_ABS_MODEL`
   - `ZCL_GMS_EXCHRATE_DPC` inherits `/IWBEP/CL_MGW_PUSH_ABS_DATA`
2. `/IWFND/MAINT_SERVICE` → **Add Service** (or register a TADIR service):
   - Technical Service Name: `ZGMS_EXCHRATE_SRV`
   - Model Provider Class: `ZCL_GMS_EXCHRATE_MPC`
   - Data Provider Class:  `ZCL_GMS_EXCHRATE_DPC`
3. Assign system alias (`LOCAL` for embedded deployment) and activate.
4. Verify metadata:
   `GET /sap/opu/odata/sap/ZGMS_EXCHRATE_SRV/$metadata`

## How CPI calls it (deep insert)

```
POST /sap/opu/odata/sap/ZGMS_EXCHRATE_SRV/ExchangeRatesSet
Content-Type: application/json
X-CSRF-Token: <fetched first via GET ...?$top=0 with X-CSRF-Token: Fetch>

{
  "REQUEST_ID": "",
  "ExchangeRate": [
    { "RATE_TYPE":"M","FROM_CURR":"USD","TO_CURRNCY":"INR",
      "VALID_FROM":"20260623","EXCH_RATE":"83.2500",
      "FROM_FACTOR":"1","TO_FACTOR":"1" },
    { "RATE_TYPE":"M","FROM_CURR":"EUR","TO_CURRNCY":"INR",
      "VALID_FROM":"20260623","EXCH_RATE":"90.1000",
      "FROM_FACTOR":"1","TO_FACTOR":"1" }
  ]
}
```

CPI notes:
- Do a `GET` with header `X-CSRF-Token: Fetch` first, reuse the returned token
  and cookies on the `POST` (standard OData V2 stateful CSRF handling).
- The navigation property name in the JSON is **`ExchangeRate`** (the child
  collection), matching the XSD child element name.
- The entire array is processed in a single `CREATE_DEEP_ENTITY` call and is
  committed/rolled back as one unit.

## Where you add the SAP update

`ZCL_GMS_EXCHRATE_DPC → process_rate( )` runs once per item. Replace the
placeholder body with your real update, e.g. `BAPI_EXCHANGERATE_CREATEMULTIPLE`
(updates `TCURR`) or a custom Z table. Return a `BAPIRET2`; any `E/A/X` rolls
back the whole batch and the messages are returned to CPI as the OData error
body.
